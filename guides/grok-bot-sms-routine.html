Use CampfireSMS with Grok Bot and Grok Build

Your phone can be the return channel for a Grok task. The piece that keeps it working is a routine that checks the Campfire bridge.

By CampfireSMS

You can use CampfireSMS with Grok Bot without running Grok Build. Install the Campfire client on the Bot’s computer, connect your phone, and give the Bot a routine to check for replies. You can then send instructions by text and receive a short response when there is something useful to report.

Grok Bot or Grok Build?

Grok Bot gives you a Bot with a computer and native routines. A webhook routine can wake it when an SMS arrives, so you do not have to keep a coding conversation actively looping. Ask the Bot to create the routine in plain language, then review and test it. See the Grok Bot routine documentation.

Grok Build is a coding agent you can run in a terminal or a scripted workflow. It can host Campfire’s tools over stdio MCP. You still need the active agent or a scheduled workflow to check the bridge; installing the connector does not create that schedule. See the Grok Build documentation.

Both use the same Campfire bridge. Grok Bot can use webhook wake; Grok Build needs an active session or scheduled workflow.

1. Connect Campfire on the computer doing the work

For the hosted MCP plugin, configure https://api.campfiresms.com/mcp using the host's secure installation credential field. Hosted MCP needs no Python or pip installation. The following steps apply to the local connector.

Verify your phone number, then run the installation command from your account on the Bot’s computer or the machine running Grok Build:

npx -y @campfiresms/setup XXXX-XXXX

Replace XXXX-XXXX with your temporary installation code. The install guide covers prerequisites and the two-way setup test. The local connector needs Node.js 18+ for setup and Python 3.12+.

Grok Build can use the registered campfire MCP server. Grok Bot can use the same installed Campfire Python client directly from its computer; Grok Build is optional. Have the Bot verify that it can open the bridge, send a test text, and retrieve your reply before scheduling anything.

On Debian, use a Python virtual environment

Debian’s system Python can reject pip installation with an externally-managed-environment error. Put the Campfire Python connector in a virtual environment. This applies to the connector whether Grok Bot or Grok Build uses it; Grok Build itself does not need to be installed inside that environment. Debian documents this requirement.

First confirm that python3 is version 3.12 or newer and has venv support. Then, in the same shell:

python3 -m venv "$HOME/.local/share/campfire/venv"
. "$HOME/.local/share/campfire/venv/bin/activate"
npx -y @campfiresms/setup XXXX-XXXX

Use the virtual environment’s absolute Python path in the MCP configuration or Bot routine. Shell activation does not carry over to every future run. For example, on a computer whose user home is /home/box, the stdio server command is:

/home/box/.local/share/campfire/venv/bin/python -m campfire_mcp.cli serve

Use your actual home path. For Grok Build, check its campfire MCP entry and replace a bare python3 command with that absolute path. For Grok Bot, use the same interpreter when calling the installed Python client.

2. Enable 24/7 webhook wake

After one successful manual SMS round trip, create an active webhook-triggered routine on the standing Bot that owns your Campfire installation. Grok Bot's routine documentation explains where to copy the POST to URL and key.

For campfire.wake.probe or action: skip, finish quietly without calling tools. For campfire.message.available, use campfire_open_bridge to reuse the active bridge, then campfire_check_messages. Process pending messages within the task's existing permissions and acknowledge each ID only after incorporating it. Track handled IDs so duplicate wakes do not repeat actions. Send a concise SMS for a result, question, or blocker. If the queue is empty, finish quietly. Close the bridge when the task is complete.

In your CampfireSMS account, open Grok Bot 24/7 wake, choose the owning Bot installation, and enter the URL and sender key. One installation owns wake per account. The key belongs in this setup form, never in a chat or SMS. Close any bridge owned by another installation before testing; its replies remain routed to that installation.

Test webhook and save sends a probe run. Acceptance confirms the webhook starts a run, not that the Bot can read or reply to SMS. Finish with a real SMS and verify the Bot's reply. Failed wake deliveries retry independently while the message remains pending; the SMS body stays in the authenticated MCP queue.

3. Know what the routine is checking

Stdio is the connection between an MCP host and the local Campfire connector. It is not an automatic wake-up signal when someone texts you. The webhook wakes the Bot, which then asks Campfire for pending replies. A local Build session still needs an active or scheduled workflow.

The MCP tools are campfire_open_bridge, campfire_check_messages, campfire_ack, campfire_send_message, and campfire_close_bridge. A Bot calling the installed Python client directly uses the corresponding client methods. Both reach the same Campfire HTTP API.

Open the bridge once, check it on each run, and acknowledge replies after handling them. Unacknowledged replies appear again on later checks. Close the bridge when the task is complete. With wake enabled, a later ordinary SMS opens a fresh Bot bridge.

Using Grok Build instead

Ask your active Build session to check Campfire at useful work boundaries and while waiting for your input. If you need checks after the session becomes idle, arrange a scheduled workflow that can run the agent with the same Campfire configuration and task context. A connected MCP server alone does not keep an idle agent working.

The machine running that workflow must stay awake and online. With Grok Bot’s native routine, the Bot’s computer does the checking, so your own laptop can be closed. In either case, account limits, paused routines, or an unavailable runtime can interrupt checks.

Test the routine before relying on it

  1. Have the agent open the bridge and send you a short test text.
  2. Reply with a harmless instruction such as “Send me a one-sentence status.”
  3. Let the webhook routine handle it, then verify you receive the response.
  4. Check the routine history and confirm it does not repeat the same action or send an empty status update.

When you finish, disable wake in CampfireSMS and pause the routine first, then ask the agent to close the bridge. This prevents the next scheduled run from reopening it.

SMS lets you steer work within the agent’s existing permissions. Native approval prompts still belong in the agent’s environment. Keep credentials and sensitive information out of texts.
