MCP messaging

MCP SMS notifications you can reply to

Let your agent text you when work needs attention, then send your answer back.

By CampfireSMS · Published October 7, 2026

An MCP SMS server gives a compatible agent messaging tools. CampfireSMS supports sending SMS updates, retrieving human replies, and acknowledging handled messages, so the exchange can continue in your existing workflow.

Give the agent a way to reach you

MCP makes a messaging service available as tools inside a compatible host. A useful notification tool lets the agent tell you that a result is ready. A two-way connection also gives it a way to read what you text back.

CampfireSMS handles phone verification, SMS delivery, the message queue, and routing. Your agent supplies the model, repository access, and execution. You can keep the coding workspace you already use.

For host-specific setup, follow Codex SMS or Claude Code SMS. Other hosts need compatible MCP configuration.

The MCP tools for a complete SMS exchange

Messaging tools exposed by the CampfireSMS connector.
ToolPurpose
campfire_open_bridgeOpen or reuse the installation's active connection.
campfire_send_messageSend a concise SMS update or question.
campfire_check_messagesRetrieve pending human replies.
campfire_ackAcknowledge message IDs after incorporating their input.
campfire_close_bridgeRelease the connection when the exchange is finished.

Pending messages repeat until acknowledged. The agent should incorporate the input before acknowledging it and check at useful task boundaries. Listing tools alone does not establish that messages reach your phone or come back to the agent.

Connect the runtime you already use

  1. Create an account and verify your phone.
  2. For a local agent, run the one-time command supplied by your account: npx -y @campfiresms/setup YOUR_INSTALLATION_CODE.
  3. Register the local MCP command in your agent and restart it. The installation guide explains automatic registration and manual host configuration.
  4. Ask the agent to open a bridge, send a harmless text, retrieve your reply, and text a confirmation.

The local route requires Node.js 18+ and Python 3.12+. Keep the computer awake and online with the agent running. Each installation has its own credential; use the account's setup command rather than putting credentials into SMS.

For Grok Bot, connect hosted Streamable HTTP MCP at https://api.campfiresms.com/mcp using secure credential settings. Follow the hosted MCP and webhook wake guide for the cloud route.

Tell the agent which moments deserve a text

Use CampfireSMS for this task. Text me when the build finishes, when a PR is ready for review, or when you need a clarification. Include the task name and one clear next step. Check for replies at meaningful work boundaries and incorporate them within the scope and permissions we already agreed. Acknowledge handled messages and close the bridge when finished.

This is an instruction for the task, not an automatic subscription to every event on the computer. A bare CI job or shell process needs an agent or integration that observes its result and calls the messaging tools.

Use the focused examples for build completion, PR review, and questions that block the next step.

Verify the return path before leaving

A received text checks outbound delivery. To check the conversation, reply with a distinctive harmless instruction such as “summarize step two.” Confirm that the agent reads that exact content and uses it in its response.

A local session must remain active to process replies. For incoming SMS that can start cloud work, configure Grok Bot webhook wake and test the complete text-to-routine-to-reply exchange.

Use SMS for task decisions within existing permissions; native permission dialogs stay in the host. If you need a future notification that outlives a session, compare notifications and persistent reminders.

Common questions

Can an MCP server send SMS and receive replies?

Yes, when it exposes both outbound messaging and an inbound message queue. CampfireSMS provides send, check, and acknowledge tools for that exchange.

Does connecting MCP automatically notify me when a build finishes?

The agent or integration must observe completion and call the messaging tool. Connection setup alone does not monitor unrelated processes.

Does hosted MCP mean my local agent keeps running after shutdown?

Hosting the messaging service does not host your local agent. Keep the local runtime available, or use the documented Grok Bot cloud wake setup.
